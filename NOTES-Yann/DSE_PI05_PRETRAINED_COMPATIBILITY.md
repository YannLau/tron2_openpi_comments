**DSE 与 π0.5 融合：官方预训练权重兼容性与能力保留分析**

日期：2026-09-24。范围：当前 tron2_openpi 的 JAX 训练与部署路径。本文是源码层面的可行性分析；没有下载、实际装载官方 checkpoint，也没有训练或真机验证。配套研究流程见 [DSE_RESEARCH_VALIDATION_PLAN.md](DSE_RESEARCH_VALIDATION_PLAN.md)。

**结论与硬约束**

可以在利用官方完整 π0.5 基座权重的基础上增加 DSE。新增模块不要求丢弃原有权重，更不要求重新预训练整个 VLA。推荐将“原有模型参数路径、形状与输入输出语义保持兼容”作为设计硬约束，将新增参数放入独立、可审计的命名空间。

必须区分三个命题：

1. 权重兼容：原有模型参数均能从基座恢复，只有新增参数独立初始化。
2. 数值保留：训练期间冻结的原有参数不被更新；需考虑加载时 dtype 转换。
3. 能力保留：启用新条件和新执行逻辑后，在未见物体、场景和语言指令上的行为仍然可靠。

前两项可以通过实现和参数检查保证；第三项必须通过实验评估。即使参数完全冻结，错误的先验也可能使策略选择错误动作。普通全参微调即使架构完全不变，也可能遗忘。

官方提供用于后训练的 `pi05_base`，当前 OpenPI 官方说明 π0.5 的公开训练/推理支持 FM 动作头。应使用完整 π0.5 checkpoint，而不是仅加载 PaliGemma 来替代完整 VLA 初始化。[OpenPI 官方说明与 checkpoints](https://github.com/Physical-Intelligence/openpi#model-checkpoints)

**当前仓库为什么需要适配，但不存在根本障碍**

- `src/openpi/training/weight_loaders.py:123`：`CheckpointWeightLoader.load` 默认以 `missing_regex=".*lora.*"` 合并参数，仅容许缺失的 LoRA 参数。直接增加 DSE 投影或辅助头，会在训练侧严格检查时因缺失键而失败。
- 同文件 `_merge_params` 按路径复制已有权重，允许显式列出的新增路径使用参考参数；它不负责修复原有张量形状变化。
- `scripts/train.py:147`：加载器接收的是 `jax.eval_shape` 得到的形状树。允许缺失的新参数先以形状占位符参与检查，随后占位符被过滤。
- `scripts/train.py:181`：实际初始化先创建完整新模型，再把已加载的真实权重写回对应位置。因此，旧参数来自官方 checkpoint，新参数沿用模块定义的随机/零初始化。

实施时为新增模块增加专用 WeightLoader 或扩展明确白名单；LoRA 以及实际新增模块路径可以缺失，任何原有路径缺失或形状不匹配都应报错。不要使用宽泛的 `missing_regex=".*"` 隐藏主干漏载。由于现有合并会忽略 checkpoint 多余键，还需在合并前生成审计报告，防止原有模块被意外重命名或删除。

结构扩展后的首次训练应作为“从基座权重初始化的新训练”，重新建立优化器和 EMA 状态；不要将旧结构的训练状态直接作为 `resume` 来源。之后再从同结构的新 checkpoint 续训。

部署路径不同：`src/openpi/models/model.py:306` 的 `BaseModelConfig.load` 只构造形状骨架并要求完整匹配；`remove_extra_params=True` 只删除多余参数，不初始化缺失模块。`src/openpi/policies/policy_config.py:131` 直接调用这一路径。因此，部署应加载训练后保存的“完整增强模型权重 + 对应配置”，或另写显式的“base + adapter”组合加载器。只修改训练侧的加载器还不能完成部署。

**各融合方案的兼容性**

| 方案 | 对原有参数的要求 | 新增参数 | 主要边界 |
|---|---|---|---|
| C-text：现有词表组成的短文本状态字段 | 不改网络，直接加载完整原权重 | VLA 内无；独立 DSE 有 | 新提示仍需验证是否被正确理解；受 prompt 长度限制 |
| C-token：投影成少量连续 prefix embedding | 保留原有模块及维度，可加载全部原权重 | DSE 投影、可选先验编码器 | 需处理加载白名单、mask、位置、缓存与部署配置 |
| A：从现有观测表征读取的辅助预测头 | 原动作路径不变，可加载全部原权重 | 辅助头 | 辅助损失更新共享参数时仍可能遗忘 |
| G：生成后的事件门控 | 原模型不变，直接加载原权重 | 独立 DSE；门控规则可无学习参数 | 会改变执行行为，且需维护 RTC 队列和手臂协调 |
| 增量残差条件分支 | 保留原模型，旧权重完整加载 | 侧分支/小型 adapter | 可设计为初始化不改变原前向，但必须验证 |
| 独立夹爪头 | 保留原 FM 动作头和维度时可完整加载 | 夹爪分类/事件头 | 覆盖夹爪输出后，实际执行依赖新头，不能只凭加载率证明继承原能力 |
| 替换原动作头、改主干宽度、直接拼大 feature 通道 | 被改模块可能尺寸不匹配 | 取决于修改 | 不作为首选；与“全部原权重兼容”的硬约束冲突 |

不确定性感知门控不是唯一的网络结构：作为外部执行逻辑时按 G 处理，作为条件融合权重时按 C-token/残差分支处理。FM 内引导可以保留权重不变，但会改变采样过程，其稳定性、梯度代价和 RTC 兼容性需另行验证。

**C-token 为什么不必改变主干矩阵**

`src/openpi/models/pi0.py:291` 的 `embed_prefix` 将图像与文本 embedding 沿序列轴拼接。可将 DSE 输出投影为相同 embedding 宽度的 K 个向量，再沿同一轴拼接：

\[
X\in\mathbb{R}^{B\times L\times d},\quad P_\phi(z)\in\mathbb{R}^{B\times K\times d},\quad X'=[X;P_\phi(z)].
\]

变的是序列长度 L，不是特征宽度 d；原 attention/FFN 权重无须因此改变形状。这里的 token 是连续向量，不需要给 tokenizer 增加 K 个词表条目或扩展词嵌入矩阵。若沿最后一维拼成 d+k，再改原层输入维度，则属于另一种设计，会产生原权重尺寸不兼容。

当前 `Pi0Config.action_dim` 默认为 32。Tron2 的物理动作维度通过既有映射、padding 与裁剪对接；增加夹爪先验时不应将模型维度直接改成 16/18 或删除原夹爪通道。必须同时保留 state/action 的归一化、绝对/增量及左右手语义。

C-text 也应使用原 tokenizer 能编码的普通文本，避免引入新词表。当前 tokenizer 将任务和离散 state 放入同一有长度上限的序列，需验证新增字段未截掉指令或 state。文本输入兼容不等于模型零样本即可可靠执行新字段。

**“新增模块为零”不一定等于原模型**

把新增 prefix embedding 初始化为零仍可能改变 attention 的归一化、位置和计算结果，不能据此宣称初始化输出完全一致。无先验时应真正绕过新分支，或完整屏蔽新增 token，并保持原 token 与动作 token 的位置语义；以实际输出一致性检查为准。

如果需要强初始化一致性，可考虑残差侧分支：

\[
h'=h+W_{out}R_\phi(h,z),\qquad W_{out}=0\text{ at initialization}.
\]

保持主路径不变、内部非零随机初始化、只将末端输出投影设为零，可使初始新增贡献为零，并保留后续学习通路。不要把所有分支权重都设为零。该分支本身仍需实现、加载与梯度验证，不能因公式成立就跳过工程检查。

关闭增强后能否恢复原行为还取决于训练方式：原参数完全冻结且主路径不变时，可以验证恢复；原参数已全参微调则无法只靠关闭 DSE 恢复官方基座。LoRA 的原始矩阵虽然冻结，启用 LoRA 后有效变换仍改变；必须同时关闭相关适配器才有机会恢复对应基准策略。

**建议采用的训练路线**

1. 从完整官方 `pi05_base` 建立共同的 Tron2 适配策略 π_base。先固定三相机、动作语义、归一化、控制频率与 RTC 设置。所有 DSE 对照从同一 checkpoint 分叉，避免不同前期训练掩盖 DSE 效果。
2. 用 C-text 和外部门控分别验证先验是否有用。外部门控可直接复用同一个冻结策略；C-text 输入虽然不改参数形状，但可能需要轻量后训练适应新字段。二者不必同时开启。
3. 正式条件方法尝试“原策略冻结 + 可训练 DSE 投影/增量分支”。该设定可保护已训练权重，但不保证适配能力足够。若效果不足，再单独比较加入动作专家 LoRA；扩大 VLM 可训练范围属于进一步实验，不作为默认起点。
4. 训练继续混入通用/恢复轨迹，并使用预测先验、先验丢弃、错误/延迟扰动。禁止用测试集回放作为抗遗忘数据。保留原策略副本，便于回退及行为对照。
5. 若需额外行为保持约束，可在允许的训练保留集上比较冻结教师与学生在相同观测、噪声、flow 时间的速度场输出。其权重需消融，避免教师约束抵消所需纠错；不要直接把 FM 输出当作自回归分布计算 KL。

当前 `src/openpi/models/pi0_config.py:231` 的 LoRA 冻结过滤器主要匹配 `llm` 路径，并不自动冻结视觉编码器、动作投影、时间 MLP 等全部原模块。要实现“只训练新增模块/指定 LoRA”，必须显式构造并审计冻结清单，打印可训练参数路径、数量与更新情况。不能仅以 variant 名字带 `lora` 作为已保护整个基座的证据。

仅训练辅助头且完全冻结共享主干、推理又不使用辅助输出时，原策略不会因为辅助损失而改进。辅助监督基线要允许共享策略接受梯度，或者让辅助输出进入动作路径，并准确说明是哪一种机制。

**兼容性与能力保留的验收**

| 检查 | 通过标准/需要报告的内容 |
|---|---|
| 参数覆盖 | 以原模型参数为分母，路径及元素覆盖率均为 100%；新增参数单独统计；原有 shape 不匹配数为 0 |
| 加载数值 | 每个旧参数等于 checkpoint 经预期 dtype 转换后的值；任何丢弃/缺失键均有解释 |
| 初始无先验行为 | 原模型与增强模型关闭新增分支时，使用同一输入处理、noise、采样步数、dtype 与 RTC 状态，输出在约定数值误差内一致 |
| 更新范围 | 小步训练后冻结参数不变；新增模块获得预期梯度/更新；零初始化分支按设计逐步产生梯度 |
| 保存部署 | 完整增强 checkpoint 重新加载后输出一致；base-only 不能被误标成已训练增强模型 |
| 泛化保持 | 与共同 Tron2 策略比较未见物体、背景、目标位置、同义指令、多物体指令区分与恢复场景，报告成功率差和置信区间 |
| 先验失效 | unknown、延迟、错误高置信先验时，记录策略与回退表现；验证“可关闭”不等于“自动回退一定可靠” |

关于“通识能力”，本项目应主要用可观测的语言条件操控能力衡量，例如同一场景下指令切换是否改变目标、未见物体描述能否定位、相似物体干扰下能否遵循任务。当前 FM 部署接口并不是通用问答测评接口，不应未经实验声称完整保留全部 VLM 通识能力。

若论文宣称泛化不退化，应提前指定可接受退化幅度和统计方案，做非劣效评估；差异不显著不等于性能相等。研究计划中的独立分组划分、重复试验和置信区间仍然适用。

最终推荐：保留 π0.5 原骨架及完整官方权重来源，以 C-text 做最低成本验证，以兼容的 C-token/增量分支作为候选正式方法，辅助头和独立夹爪头作为控制组，外部事件门控作为独立可开关执行组件。模型结构可以增量扩展；原有参数必须可完整追溯，增强后的泛化能力必须单独证明。
